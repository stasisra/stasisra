Участник хранится как отдельная роль. Прежние назначения контрагента сохранены и учитываются общим фильтром людей. Старые мероприятия доступны по варианту «Без типа». Итог остаётся в мероприятии, рабочая задача хранит добавленную копию со ссылкой на источник. Повторное добавление обновляет копию.

## Проверка обновления

Использована полная поставка `task-gantt-app-next.zip` версии 0.4.1 с проверенной контрольной суммой и собранным каталогом `.next`. После проверки запуска на порту 3003 из неё подготовлены две отдельные копии. В обеих были прежний архив сборки в `_updates` и синтетические данные, включая запись в WAL.

- **Установка из ZIP.** Запущен помощник из распакованного пакета 0.4.2. Он сохранил прежнюю сборку, создал согласованную копию SQLite, применил миграцию и собрал приложение с общими библиотеками. Сверены существующие записи и столбцы всех 23 таблиц, включая историю миграций, импорт, связи, назначения, комментарии и байты вложений. Проверены целостность SQLite и внешние ключи, прежние `.env` и ссылка `node_modules`. После запуска на 3003 проверены вход прежним паролем, карточка, файл и сохранённый в браузере профиль печати.
- **Откат после сбоя.** После реальной миграции сымитирован сбой сборки с частично записанным каталогом `.next`. Помощник восстановил прежнюю базу и номер версии. Контрольные суммы всех файлов прежней `.next` и содержимого `public` совпали. Версия 0.4.1 снова запустилась на 3003, прошли вход и чтение исходного файла.
- **Проверки до изменений.** Помощник остановился при работающем сервере на 3003. Автоматический тест с изменённым файлом пакета подтвердил остановку по контрольной сумме до записи в установку.

Проверки проведены под Linux с Node.js 24 и Chromium. Команды `npm run typecheck`, `npm run lint`, `npm run check:workspace` и производственная сборка выполнены успешно. Прошли 42 автоматических теста и 20 браузерных сценариев. Для Windows проверены структура архива и сценарий обновления на тех же исходниках и зависимостях. Запуск `.cmd` под Windows остаётся непроверенным.
