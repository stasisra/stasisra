# Task & Gantt Workspace 0.2

Локальное приложение для одного администратора: тема / проект → задачи и мероприятия → подзадачи. SQLite хранит задачи, обсуждения и файлы. Next.js обслуживает вход и API; рабочий интерфейс — HTML/CSS/JavaScript с локальными средствами просмотра документов.

## Обновление существующей Windows-установки

1. Распакуйте папку **task-gantt-app-workspace** из архива в **C:\Distr_Local**. Внутри должны лежать `install-workspace.cmd`, `start-workspace.cmd`, `package.json`, `app`, `prisma`, `public`, `workspace`.
2. Запустите **install-workspace.cmd** двойным щелчком. Установщик использует Node из соседней `node-v22.23.4-win-x64`, если эта папка есть; иначе установленный Node 22.12+ или 24. Для первого скачивания зависимостей нужен Интернет.
3. После сообщения `Installation complete` запустите **start-workspace.cmd**. Откройте **http://127.0.0.1:3002** и войдите с прежними email и паролем администратора.

Установщик читает базу из соседней `task-gantt-app-fixed` и создаёт независимую копию через SQLite backup API, включая WAL работающей программы. Старые файлы, пароль и база не заменяются. Новая копия использует собственный секрет и имя сессионной cookie. Старая программа на 3001 продолжает работать отдельно.

**Копии после установки не синхронизируются.** Дальнейшие изменения вносите в новой программе. Повторный запуск установщика сохраняет уже созданные `.env` и `prisma/dev.db`, применяет недостающие миграции и пересобирает программу. Если осталась только часть настроек, он останавливается, ничего не перезаписывая. Окно `start-workspace.cmd` нужно оставлять открытым; Ctrl+C в нём останавливает эту копию.

При ошибке оставьте окно открытым и сохраните текст ошибки. Не запускайте `npm audit fix --force`.

## Перенос структуры

`npm run db:init` добавляет таблицы и поля SQL-миграциями. `npm run db:upgrade` один раз переносит смешанные теги по согласованной классификации из `config/tag-classification.json`. Повторный запуск не создаёт дубликатов.

- Темы выделяются в отдельный справочник. Ветка имеет одну тему; перенос родителя переносит и потомков.
- Контрагенты — общий справочник людей, организаций и групп; исполнителей у задачи может быть несколько. Ответственный выбирается из того же справочника, но имеет отдельную роль.
- Первоначальные ответственные: Патрик, Меликантова, Аркадий, Наташа архитектор, Юрай. «Наташа дизайнер» объединяется с «Наташа архитектор». Юрист и Юрай остаются разными карточками.
- Козуб удаляется из назначений и справочников; в составном назначении «Козуб, Стас» остаётся Стас. История и тексты задач сохраняются. Старые учётные записи не удаляются.
- «ТЗ сайт» становится родительской задачей внутри web; уже существующие вложенные ветки сохраняются. Неоднозначные назначения не угадываются: задачи без однозначной темы доступны в разделе **Без темы**. Исходные теги можно посмотреть в карточке.
- Старые назначения сохраняются в `legacyAssignments`, теги — в `legacyTags`, отчёт переноса — в `WorkspaceMeta`. Эти поля не содержат пароль администратора. При старых назначениях вне пяти новых ответственных контакт сохраняется до явной замены.

После первого переноса проверьте **Без темы**, назначения ответственных и группы, созданные из тегов. На вашей фактической базе перенос выполнится при установке; облачные проверки используют синтетические данные.

## Рабочие экраны

- **Задачи**: группировка по темам, подзадачи, описание, статус, сроки, несколько исполнителей и один ответственный. У мероприятия есть время, часовой пояс и место; процент выполнения показывается только у задач.
- **Фильтры**: несколько тем объединяются через «или», исполнитель / ответственный / статус / поиск / период — через «и». Можно выбирать пересечение срока с периодом, дату начала или дедлайн; обе границы включены. Изменив фильтры, нажмите **Применить**. Отфильтрованные подзадачи видны с путём родителя, даже если сам родитель не подходит.
- **Дедлайны**: отдельный экран, быстрые периоды сегодня / 7 / 30 дней / просроченные, либо свои даты.
- **Гант**: тот же набор фильтров, переход по трёхнедельным диапазонам.
- **Комментарии / вопросы**: прямо под строкой задачи либо в карточке. Enter добавляет запись, Shift+Enter переносит строку. Открытые вопросы сразу видны; вопрос можно решить и открыть снова.
- **Справочники**: добавление, переименование, скрытие, восстановление, удаление с заменой. Снятие роли ответственного оставляет контакт. Удаление темы или человека не удаляет задачи.
- **Удаление задачи**: удаляется выбранная задача с её обсуждением и файлами. Её непосредственные подзадачи переходят к её родителю; их содержание сохраняется.

Поля карточки сохраняются кнопкой **Сохранить**. Комментарии и файлы существующей задачи сохраняются сразу. У новой задачи они остаются в черновике до первого сохранения; при сбое загрузки файлы доступны для повторной попытки. Изменения одного окна не перезаписывают более новую версию другого окна: сервер проверяет ревизию записи, а отвергнутый черновик остаётся в форме.

## Вложения и просмотр

До **20 МБ на файл**, содержимое — в SQLite. Можно прикрепить, открыть, скачать оригинал или удалить файл. Просмотр Word **DOCX**, Excel **XLSX / XLS / XLSB / XLSM / ODS**, PDF, изображений и текста работает локально, без передачи документов внешнему сервису. В Excel можно переключать листы и просматривать большие таблицы порциями.

DOCX и таблицы отображаются для чтения: макросы не запускаются, формулы не пересчитываются, оформление может отличаться от Office. Старый Word **DOC**, документы с паролем и неподдерживаемые файлы скачиваются для открытия в установленной программе; DOC можно предварительно сохранить в DOCX. Очень большие или повреждённые документы могут не открыться во встроенном просмотре; оригинал сохраняется.

Вложения, которые очень старая версия хранила только в IndexedDB браузера, автоматически не переносятся. Файлы, уже сохранённые текущей версией в SQLite, копируются вместе с базой.

## Печать и экспорт

Кнопка **Печать / экспорт** открывает обычный список или лист для встречи. Источник — текущая выборка с дополнительными фильтрами либо задача со всеми её подзадачами. Настройте столбцы, включите **Описания**, вопросы, комментарии и названия файлов. В листе встречи есть место для рукописных пометок и общих итогов.

Можно снимать задачи, менять порядок соседних записей, задавать разрывы страниц, ориентацию, шрифт и плотность. Предпросмотр разбивается на настоящие листы A4. **Печать / PDF** открывает системную печать браузера; выберите принтер либо «Сохранить как PDF». Для совпадения с предпросмотром выберите A4, масштаб 100%, отключите колонтитулы браузера. CSV и XLSX содержат те же выбранные строки и включённые текстовые сведения. В браузере запоминается только оформление печати, задачи хранятся на сервере.

## Установка вручную / разработка

Node.js **22.12+ или 24**, npm; Docker не требуется. Из корня проекта:

```bash
npm ci --ignore-scripts
npm rebuild better-sqlite3
npm run prisma:generate
```

Для переноса из другой папки в пустую новую установку:

```bash
node scripts/setup-workspace.cjs "C:/путь/к/task-gantt-app-fixed"
npm run db:init
npm run db:upgrade
npm run build
npm start -- --hostname 127.0.0.1 --port 3002
```

Для новой пустой базы скопируйте `.env.example` в `.env`, задайте случайный `AUTH_JWT_SECRET` длиной минимум 32 символа, `ADMIN_EMAIL` и `ADMIN_PASSWORD` (минимум 12 символов), затем `db:init`, `db:upgrade`, `db:admin`. Команда `db:admin` создаёт / явно меняет пароль ADMIN, но не создаёт демонстрационных задач. Для существующей базы её запускать не нужно.

`DATABASE_URL="file:./dev.db"` означает `prisma/dev.db`; абсолютный путь тоже поддерживается. `APP_URL="http://127.0.0.1:3002"` разрешает локальную production-cookie через HTTP только для loopback. Для внешнего адреса нужен HTTPS. `APP_TIME_ZONE` задаёт календарный часовой пояс приложения; по умолчанию `Asia/Jerusalem`, в мероприятии он выбирается отдельно. Режим разработки: `npm run dev -- --hostname 127.0.0.1 --port 3002`.

Резервная копия всей программы должна включать SQLite вместе с вложениями. Для простой файловой копии сначала остановите сервер; не копируйте один `dev.db` работающего сервера без WAL. Установщик использует согласованный SQLite backup и этого ограничения не имеет.

## Проверки и устройство

```bash
npm run typecheck
npm run lint
npm run check:workspace
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты требуют production-сборки, создают отдельную временную БД и ADMIN, запускают сервер на 3100. Для установленного Chromium: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`. Результаты и ограничения — в `CHECKS.md` и `FIXES.md`.

`workspace/index.html`, `public/workspace/app.js`, `workspace.css` — рабочий интерфейс, без демонстрационных данных; `/tasks`, `/gantt`, `/deadlines` отдают его через авторизованный HTML route handler. `lib/workspace/service.ts` — валидированные операции и ревизии, `migrate.ts` — классификация, `/api/workspace` — защищённые GET-снимок и POST-действия. Вложения обслуживаются отдельным API. Прежние адреса страниц перенаправляются на новые экраны. Прежние API изменения задач, комментариев и справочников возвращают 410: они не должны обходить новые связи и ревизии. Старые GET-экспорты сохранены для совместимости со старым форматом, новый интерфейс использует собственную единую выборку.

Prisma использует JS/WASM и `@prisma/adapter-better-sqlite3`; закреплённый override исключает старый нативный SQLite-драйвер 11.10.0, вызывавший падение на Node 24. Локальные Office-библиотеки, источники, контрольные суммы и лицензии — `public/workspace/vendor`. Шрифт старого серверного PDF — DejaVu Sans, лицензия в `assets/fonts/LICENSE.txt`. Согласованный макет `docs/ux-prototype.html` сохранён в репозитории отдельно и в архив рабочего приложения не включён.
