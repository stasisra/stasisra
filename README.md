# Task & Gantt 0.4.1 — удобные карточки и контакты

Локальная программа для одного администратора. Рабочая структура: **тема с описанием → задача → подзадачи любой глубины**. Отдельно — **мероприятия**: встречи, поездки, совещания, собственные вопросы, подготовительные дела, материалы и итоги. Одно мероприятие связывает задачи нескольких тем; рабочие задачи сохраняют своих родителей и назначения. В Ганте отображаются только рабочие задачи.

Полное согласованное описание: [docs/product-description-ru.md](docs/product-description-ru.md).

## Обновление уже работающей task-gantt-app-next на порту 3003

1. Остановите только программу на **3003**: Ctrl+C в окне её запуска.
2. Распакуйте **task-gantt-update-0.4.1.zip отдельно**, например в **C:\Distr_Local\task-gantt-update-0.4.1**.
3. Запустите **update-next.cmd**, дождитесь **Update complete**. При другом пути приложения передайте его аргументом: `update-next.cmd "C:\путь\к\task-gantt-app-next"`.
4. В прежней папке **C:\Distr_Local\task-gantt-app-next** запустите **start-next.cmd**.
5. Откройте **http://localhost:3003**, обновите страницу **Ctrl+F5**.

Версия 0.4.1 исправляет ошибку сборки из файлов резервной копии `_updates/.../previous-build/types`. Если прежнее обновление завершилось сообщением **Update rolled back**, закройте окно ошибки и выполните эти шаги с новым архивом 0.4.1. Существующие резервные копии остаются на месте; удалять `_updates` не требуется.

Сохраняются текущая база, импортированные записи, тестовая тема, новые задачи, комментарии, файлы, логин и настройки. Повторный импорт Excel не требуется. Перед изменениями помощник сверяет контрольные суммы пакета, проверяет остановку сервера, создаёт согласованную копию SQLite через backup API и сохраняет прежний код/сборку в **_updates**. Добавляется схема контактов, программа пересобирается на уже установленных библиотеках. При ошибке миграции или сборки восстанавливаются прежняя база, код и сборка. Не копируйте payload вручную поверх работающей программы.

После скачивания пакета Интернет не нужен при полностью установленной прежней версии. npm, переустановка библиотек и генерация Prisma не выполняются. Папку **task-gantt-app-workspace** оставьте: оттуда используются библиотеки. Установочный архив ниже предназначен для отдельной новой установки, а для текущей рабочей базы используется пакет обновления.

## Новые карточки и ввод

Карточки задач и мероприятий открываются широко: слева дерево, справа выбранная запись. Нажатие на другую запись сохраняет изменённую карточку перед переходом; при ошибке ввода или конфликте правки остаются в редакторе. У каждого пункта меню **⋯**: редактировать, добавить вложенный пункт/мероприятие, переместить, выше/ниже, вывести отдельно/ветку, удалить. У пункта со связанной рабочей задачей отдельно доступны её открытие и удаление связи с мероприятием. Ввод и назначения этого пункта относятся к контексту мероприятия.

В дереве доступны поиск, фильтр по человеку, группировки по иерархии, темам, контрагентам, исполнителям и ответственным. Галочка у родителя выбирает ветку; отдельных потомков можно снять. **Вывести выбранное** открывает A4 с выбранными записями и группировкой, полными описаниями, вопросами и материалами; CSV/XLSX берут ту же выборку. Вручную группируйте повестку родительскими вопросами/пунктами и перемещением между ними.

Описания темы, задачи и мероприятия растут по содержимому и разворачиваются на весь экран кнопкой **Развернуть редактор**. Ввод `@` открывает поиск по контактам, рабочим задачам и мероприятиям текущей темы; мероприятие учитывает все связанные темы и собственных участников. Дополнительные слова сужают список, выбор — мышкой, стрелками/Enter, закрытие — Esc. Есть **Все записи** и создание контакта. В текст вставляется ссылка на карточку, назначение роли выполняется отдельно. В базе ссылки сохраняются в описании как `@[кодированное имя](contact|item:ID)`, интерфейс и печать показывают читаемые имена; не редактируйте служебный формат напрямую в базе.

Общая карточка контакта содержит компанию, должность, телефоны, email, адреса, ссылки и примечания. Телефоны/адреса допускают несколько строк. Контакт можно явно связать с несколькими темами; темы назначенных ему задач и мероприятий также участвуют в поиске. В справочнике есть поиск по данным и фильтр по теме. Одну карточку используют во всех ролях.

При сохранении новых назначений контактов с заполненными данными появляется один запрос **Добавить контактные данные в описание?** для всех выбранных людей. Выберите поля либо **Только связать**. Блок добавляется к описанию, повторное сохранение его не дублирует. Кнопка **Вставить / обновить контактные данные** доступна и позднее. Вставленные сведения являются копией на этот момент, обновляются явно; в печати их можно выключить галочкой **Контактные данные**.

## Установка рядом с действующей программой на Windows

1. Распакуйте `task-gantt-app-next.zip` в `C:\Distr_Local`. Получится **C:\Distr_Local\task-gantt-app-next**; внутри находятся `setup-next.cmd`, `start-next.cmd`, `package.json`, `app`, `prisma`.
2. Соседнюю **task-gantt-app-workspace** оставьте: установщик читает оттуда вход администратора и использует её уже установленные библиотеки. Node берётся из **C:\Distr_Local\node-v22.23.4-win-x64**, если эта папка есть; иначе нужен установленный Node 22.12+ или 24.
3. Двойным щелчком запустите **setup-next.cmd**. Дождитесь `Setup finished` (первая сборка занимает несколько минут). Интернет не нужен, если действующая программа установлена полностью. При ошибке сохраните текст из окна.
4. Запустите **start-next.cmd**, откройте **http://127.0.0.1:3003**, войдите с прежними email и паролем.

Новая база сначала пустая: копируется только вход ADMIN. Задачи загружаются отдельно после отбора. Существующая программа на 3002 продолжает работать независимо. Обе копии не синхронизируются. Сессионные cookie различаются.

Повторный запуск `setup-next.cmd` сохраняет новые задачи, файлы, настройки и пароль, затем пересобирает программу. При неполной установке помощник останавливается без перезаписи. Не распаковывайте новую версию поверх старой. При другом пути исходной программы: `node scripts/setup-next.cjs "C:/путь/к/task-gantt-app-workspace"` из папки новой версии.

Новая папка использует ссылку Windows junction на **node_modules** прежней установки. Поэтому пока **не удаляйте старую папку и её node_modules**. Старая база и исходники не изменяются. Нельзя запускать `npm ci`, `npm install`, `npm rebuild` или генерацию Prisma в новой папке с общей ссылкой: это изменит общие библиотеки. Если хотите сделать установку полностью независимой, сначала замените ссылку собственной копией node_modules или установите зависимости в отдельной чистой папке.

Окно `start-next.cmd` оставьте открытым; Ctrl+C останавливает эту копию. Прямой запуск `.cmd` на Windows в облаке не проверялся; помощник и сборка проверяются на Linux.

## Выгрузка текущей базы в Excel и отбор

Отдельный пакет [task-gantt-export-review.zip](https://raw.githubusercontent.com/stasisra/stasisra/94565550fd18f1e9800017f4cbc82811f8713985/downloads/task-gantt-export-review.zip): распакуйте и запустите **export-to-excel.cmd**. Работающую программу останавливать не требуется. Выгрузка читает настоящую локальную SQLite, включая WAL; Интернет после скачивания не нужен.

В открывшейся папке **exports\review-…** редактируйте **tasks-review.xlsx**, лист **«Отбор задач»**. В колонке **«Решение»** отмечайте **Оставить / Удалить**. Строки, номера и скрытые ID сохраняйте; сортировать и фильтровать можно. Дополнительные жёлтые поля необязательны: новый тип, название, тема, родитель № и комментарий. Новый родитель `0` означает корень. Комментарий к отбору сохраняется как исходное сведение, не меняет описание задачи. Длинные тексты есть на листе «Полные тексты» и полностью — в data.json.

Сохраните всю папку выгрузки: **data.json**, **files**, **database-full.db**, **manifest.json**, Excel. Полная база остаётся локально; для совместного разбора сначала достаточно прислать только Excel.

## Импорт после очистки

В новой программе нажмите **Импорт Excel**, выберите отредактированный Excel и папку исходной выгрузки. Предпросмотр показывает оставленные записи, типы, темы, число файлов и предупреждения. До нажатия **«Импортировать отобранное»** рабочие записи не создаются. Загружаются только оригиналы вложений выбранных задач; полная database-full.db не отправляется.

Служебные ID и контрольные суммы проверяются. Оставленный ребёнок удалённого родителя сохраняется под ближайшим подходящим оставленным родителем либо в корне. Старые рабочие задачи внутри мероприятий становятся рабочими карточками с отдельными ссылками в повестке. Собственный вопрос/подготовка требует родителя-мероприятия. Повторный импорт того же отбора не создаёт дублей; другой отбор уже импортированного снимка отклоняется. Другой снимок со совпадающими ID требует отдельного разбора. Источник не изменяется.

## Работа

- В справочниках создайте темы и их проблематику, контрагентов, ответственных и свободные теги. Один контакт может выполнять несколько ролей. Доступны изменение, скрытие, возврат и удаление с заменой связей; сами задачи сохраняются.
- Создайте задачу с названием; сроки необязательны. В карточке добавляйте подзадачи и связанные мероприятия. Одинаковые названия в разных ветках допустимы, путь помогает различать их.
- В мероприятии подключайте рабочие задачи из нескольких тем, создавайте свободные вопросы, заметки, подготовительные дела и вложенные мероприятия. У каждого пункта собственные контрагенты, исполнители и ответственный. Вопросы можно фильтровать по тексту и контрагенту.
- Сохраните итоги в карточке мероприятия, отмечайте ответы на вопросы. Собственный пункт можно **«Добавить в тему»**: он станет рабочей задачей, сохранив файлы и обсуждение, а в мероприятии останется ссылка.
- Быстрые вопросы и комментарии доступны в строке и карточке: Enter отправляет, Shift+Enter добавляет строку. При ошибке черновик сохраняется.
- Фильтры: несколько тем галочками, рядом дерево задач с поиском, выбор веток и исключений внутри них, люди по ролям, теги включить/исключить (любой/все), статус, период по началу/дедлайну/пересечению. После выбора нажимайте **Применить**. Группировки — по темам, людям, мероприятию, статусу, сроку. Общий поиск охватывает задачи, мероприятия и вопросы.
- **Мероприятия**: список и календарь; **Дедлайны**: сегодня, 7/30 дней, просроченные и свой период; **Гант**: рабочие задачи тем.

## Файлы и вывод

До **20 МБ на файл**, оригинал хранится в SQLite. Локальный просмотр DOCX, XLSX/XLS/XLSB/XLSM/ODS, PDF, изображений и текста. Excel переключает листы и показывает большие таблицы порциями. DOC и неподдерживаемые файлы скачиваются для открытия в установленной программе. Макросы и формулы не исполняются; сложная вёрстка может отличаться от Office.

**Печать / экспорт**: обычный список или лист встречи; текущая выборка, ветка с потомками либо мероприятие с повесткой. Можно выбрать строки и порядок, полные описания, людей, вопросы/комментарии, файлы, графики/изображения, место для рукописных заметок, разрывы страниц, размер шрифта и ориентацию. Предпросмотр A4. Печать / PDF использует системную печать браузера; CSV/XLSX содержат те же выбранные строки и включённые текстовые сведения. Для PDF: A4, масштаб 100%, отключить колонтитулы браузера.

## Разработка и хранение

Самостоятельная чистая установка зависимостей: Node 22.12+ / 24, `npm ci --ignore-scripts`, `npm rebuild better-sqlite3`, `npm run prisma:generate`. В отдельной пустой базе настройте `.env` (DATABASE_URL, случайный AUTH_JWT_SECRET минимум 32 символа, APP_URL), выполните `npm run db:init`, создайте ADMIN через `ADMIN_EMAIL`/`ADMIN_PASSWORD` и `npm run db:admin`, затем `npm run build`. **db:upgrade для модели 0.3/0.4 не требуется**: это старая классификация тегов с фиксированным справочником.

`DATABASE_URL="file:./dev.db"` означает prisma/dev.db. Для резервной копии остановите новую программу и сохраните всю базу с вложениями. При работающей программе используйте SQLite backup API; одного файла dev.db без WAL недостаточно.

Проверки: `npm run typecheck`, `npm run lint`, `npm run check:workspace`, `npm test`, `npm run build`, затем `npm run test:e2e`. Последний требует Chromium; можно указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`. Тесты используют отдельные синтетические базы и сервер 3100.

Новая модель: SQL-миграция **20261101000100_product**, `lib/product`, `/api/next`, `public/workspace/product-ui.js`. Prisma используется для входа/исторических таблиц; новые сущности обслуживаются параметризованным SQL и транзакциями, их нет в Prisma Client. Структуру меняют SQL-миграции через db:init; `prisma db push` применять нельзя. Старые Task и /api/workspace сохранены для чтения старых данных; рабочий интерфейс обращается к /api/next. Старые API экспорта отражают старые таблицы, поэтому новый экспорт выполняется из окна **Печать / экспорт**.

Версия 0.4 добавляет миграцию **20261103000100_contact_profiles** (поля Contact и ContactProject). Новые браузерные модули: mentions.js, card-tools.js, card-tree.js. Подготовка пакета обновления: `python3 scripts/package-card-update.py`.
