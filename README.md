# Task & Gantt — один администратор

Next.js + React + Prisma + SQLite. Все задачи доступны администратору независимо от `ownerId`. Регистрация отключена. Существующие пользователи в БД могут оставаться исполнителями, но войти в приложение может только ADMIN.

## Требования

Node.js 22 LTS (22.12+) и npm. Node 24 также поддерживается. Docker и PostgreSQL не нужны. Зависимости фиксируются `package-lock.json`.

## Первый запуск

Из корня проекта:

```bash
npm ci --ignore-scripts
npm rebuild better-sqlite3
npm run prisma:generate
cp .env.example .env
```

На Windows копировать `.env.example` в `.env` можно через Проводник или PowerShell `Copy-Item .env.example .env`.

В `.env`:

- `DATABASE_URL="file:./dev.db"` — файл `prisma/dev.db`. Можно указать абсолютный путь к SQLite-файлу.
- `AUTH_JWT_SECRET` — свой случайный ключ длиной минимум 32 символа. Сгенерировать локально: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — нужны только для создания/смены пароля администратора; пароль минимум 12 символов.

```bash
npm run db:init
npm run db:admin
npm run dev
```

Открыть приложение на порту 3000. В рабочей базе с существующим ADMIN выполнять `db:admin` не нужно: входите с прежними email и паролем. Команда `db:admin` не создаёт демонстрационные задачи и не трогает задачи.

## Подключить сохранённую базу с задачами

1. Остановить приложение.
2. Поместить свою SQLite-базу в `prisma/dev.db` либо указать её путь в `DATABASE_URL`.
3. Выполнить `npm run db:init`, затем `npm run dev`.

`db:init` применяет недостающие SQL-миграции, включая таблицу вложений; повторный запуск не создаёт задачи и не сбрасывает БД. Ожидается база этого проекта с `_prisma_migrations`. Если истории нет либо миграция изменена/не завершена, команда останавливается с объяснением. Дата задач и таблицы существующей БД сохраняют формат Prisma SQLite; заполнение владельцев не требуется, администратор видит всё.

Текущую пользовательскую базу в поставляемый архив не включали. Приложение проверялось на отдельной тестовой базе.

## Повседневная работа

- Создание/редактирование задач, подзадачи, комментарии, проценты и даты.
- Точные теги, единые фильтры таблицы, Ганта и экспортов.
- CSV, XLSX и PDF с кириллицей — кнопки на странице Tasks.
- Справочники — `/dashboard/dictionaries`.
- Новые вложения хранятся внутри SQLite, максимум 10 МБ на файл. Они доступны из другого браузера при подключении к тому же серверу. Старые вложения из IndexedDB автоматически не переносились: при необходимости их можно добавить заново.
- При удалении родителя его подзадачи остаются самостоятельными задачами. Комментарии и вложения удалённой задачи удаляются вместе с ней.
- Статус и процент — независимые редактируемые поля, автоматического завершения по проценту нет. По умолчанию DONE скрыт; его можно включить фильтром.

## Проверки

```bash
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты требуют предварительной production-сборки. Они запускают сервер на порту 3100 и создают собственную временную БД и тестового администратора. Рабочая база не используется. В облаке с установленным Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`.

## Рабочий запуск

```bash
npm run build
npm start
```

Для публикации на внешнем адресе нужен HTTPS: сессионная cookie в production имеет Secure. Для локальной разработки используйте `npm run dev`. Поддержка одного администратора не означает публичный доступ без входа.

## Устройство

`lib/validators.ts` — входные данные задач; `lib/taskRelations.ts` — связи и защита от циклов; `lib/taskQuery.ts` и `lib/tasks.ts` — общая фильтрация и безопасные данные для интерфейса; `lib/dates.ts` — календарные даты; `lib/session.ts` — сессии; API вложений сохраняет Blob в SQLite. Это основа для дальнейшей работы над UI/UX.

Prisma использует JS/WASM-компилятор и SQLite-адаптер, без нативного query engine Prisma. Скрипт генерации опирается на закреплённую ветку Prisma 6.19; SQLite-драйвер устанавливается отдельно командой `npm rebuild better-sqlite3`.
