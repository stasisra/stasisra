# Исправленная основа для дальнейшей работы над UI/UX

Приложение настроено под одного администратора. Существующие задачи доступны независимо от владельца. Регистрация отключена. Перенос владельцев и сложная многопользовательская модель не требуются.

## Что исправлено

- Рабочая production-сборка, проверка типов и ESLint; закреплена ветка Next 15.5.28, обновлены React, Prisma и валидация.
- SQLite работает через Prisma JS/WASM и нативный SQLite-адаптер; нативный query engine Prisma скачивать не нужно.
- Валидация создания и изменения задач: действительные даты, диапазон при одиночном PATCH, статусы, проценты, существование назначений, отсутствие циклов родителей.
- Полный доступ единственного ADMIN ко всем задачам, включая задачи старой базы с пустым ownerId.
- Устранён XSS через next/return; полные записи пользователей и passwordHash не отправляются клиентским компонентам.
- Повторное сохранение после ошибки, запрет случайного повторного создания, переходы после удаления с 303.
- Общая фильтрация таблицы, Ганта, dashboard и CSV/XLSX/PDF: точные теги, нормализованные имена, статусы и даты.
- Гант корректно обрабатывает задачи вне горизонта, режим прошлой недели и календарные даты.
- Состояние exp=0 больше не сбрасывается; очищенные фильтры больше не восстанавливаются из устаревшей записи Tasks.
- Исправлены все три экспорта; PDF использует шрифт с кириллицей и колонки по размеру страницы; CSV нейтрализует формулы.
- Новые вложения хранятся в SQLite, ограничены 10 МБ и доступны через защищённый API. Удаляются вместе с задачей. Предпросмотр активных HTML/SVG не исполняется.
- Справочники загружаются без ошибки агрегирования дат, объединяются в транзакции без лимита 5000 задач; фильтры и создание используют общие подсказки.
- Исправлены маршруты настроек и вложенный print layout; добавлены регрессионные проверки, браузерные сценарии и CI.

## Границы результата

- Пользовательскую базу в этой работе не загружали и в архив не включали. Проверки используют отдельные временные SQLite-базы; инструкция подключения своей базы — README.md.
- Старые вложения, сохранённые браузером до этих изменений, автоматически не импортируются. Их можно добавить заново.
- Статус и процент выполнения пока независимы; удаление родителя оставляет дочерние задачи самостоятельными. Это явно сохранённые правила, которые можно поменять вместе с UI/UX.
- Проверки выполнены на Linux / Node 24.19.0 / Chromium; запуск на Windows здесь не выполнялся. Для установки рекомендуется Node 22 LTS с готовыми бинарными пакетами SQLite.
- Предупреждения npm audit по части транзитивных зависимостей остаются. Последний отчёт после обновления: 0 critical, 11 high, 9 moderate (20 записей, включая инструменты Prisma через peer-зависимости). Их нельзя считать устранёнными; применимость к рабочим маршрутам отдельно не подтверждалась. Принудительный откат ExcelJS или миграция на Prisma 7/Next 16 в этот пакет не включены. Это ограничение для решения о внешней публикации, а не препятствие локальной работе над интерфейсом.

Команды установки, подключения БД и проверок находятся в README.md. Исходный секретный .env, база пользователя, node_modules, .git и старые сборочные результаты не входят в передаваемый архив.

Добавлено согласование уже существующей NamePolicy с историей миграций: проверка структуры, добавление отсутствующего ownerId без пересоздания Task, сохранение данных и транзакционный откат при несовместимости.
